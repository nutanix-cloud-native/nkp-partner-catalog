# AGENTS.md — NKP Catalog docs site

Guidance for agents working in `docs/`. This is the documentation site for
the NKP Catalog (partner + Nutanix product + AI application catalogs). It is a
Docusaurus 3 app. Authored markdown lives in `docs/source/`; the Docusaurus
project lives in `docs/site/`.

Live production URL:

`https://nutanix-cloud-native.github.io/nkp-partner-catalog/`

(`baseUrl` `/nkp-partner-catalog/`, `url` `https://nutanix-cloud-native.github.io`)

Read this file before changing docs content, the catalog browser, build
recipes, export pipeline, or the GitHub Pages workflow.

---

## 1. First principles

1. **Run all `just` recipes from `docs/`**, not the repo root. The root
   `justfile` does not import these recipes.
2. **Never hand-edit generated catalog pages or `source/cli/<version>/`.** `just generate-catalog` wipes
   `site/static/catalog-icons/` immediately, then walks apps (writing icons as
   it goes). Only after a successful walk does it write `catalog-data.json` and
   wipe/rewrite `source/applications/` (including `_category_.json` and
   `index.mdx`). A duplicate-name failure leaves `applications/` untouched and
   may leave icons empty or partial.
3. **Do not use `npm run deploy` or `npm run start` as the normal path.** Use
   the `just` recipes below. `site/package.json` scripts are lower-level and
   some of them actually push to GitHub.
4. **Do not push `gh-pages` unless the user explicitly asked to publish.**
   `just docs-deploy` only stages a local clone; it does not commit or push.
5. **Production deploys are CI.** Pushes to `main` that touch `docs/**`, a
   nightly cron, or `workflow_dispatch` run `.github/workflows/deploy-docs.yaml`.
6. **Broken links fail the build** (`onBrokenLinks: 'throw'`). Markdown-only
   broken links warn (`markdown.hooks.onBrokenMarkdownLinks: 'warn'`).
7. **Node 20** is the supported runtime (devbox + `engines.node >= 20`).
   Prefer `devbox run -- just <recipe>` from `docs/` to match CI. System Node
   25 may appear to work and then fail on Docusaurus/native addons.
8. **Search only works on a production build** (`docusaurus serve` of `build/`),
   not on `docusaurus start`. That is why `just docs-local` builds then serves.
9. **Human-editable docs knobs live in `source/config.yaml`** (not buried in
   React constants). Today: `applications` (NKP floor / GA ceiling for the
   catalog dropdown) and `cliDocs` (which CLI minors to generate). Prefer
   adding new toggles there over new hardcoded lists in components.
10. **CLI docs stay minimal and structural:** short landing, hierarchical
    command tree, quiet detail pages. See §7 “CLI UX principles” before
    redesigning CLI UI — do not invent curated IA without asking and hide the shared left
    nav on `/cli`, .

## 3. Commands (cwd is always `docs/`)

Preferred:

```bash
cd docs
devbox run -- just <recipe>
```

Bare `just` is fine if Node 20, `just`, and Chrome/Chromium are already on PATH.

### `just generate-catalog [root]`

Crawls sibling catalog repos and rewrites generated catalog content.

- Default `root` = parent of this git checkout (`docs/../../` → the
  `nutanix-cloud-native` directory).
- Expected siblings next to `nkp-partner-catalog`:
  - `nkp-ai-applications-catalog`
  - `nkp-nutanix-product-catalog`
- CI passes `"${GITHUB_WORKSPACE}"` because the workflow checks the three
  repos out as siblings under the Actions workspace.
- Override: `just generate-catalog /other/org-root`
- NKP filter ceiling: `MAX_GA_NKP_VERSION=2.20 just generate-catalog`
  (default ceiling is `applications.maxGaNkpVersion` in `source/config.yaml`).
- Direct script flags: `--root`, `-o`/`--output`. `-o` relocates **both**
  `catalog-data.json` **and** the generated `applications/` directory (it is
  always `dirname(output)/applications`). Icons always go to
  `site/static/catalog-icons/` regardless of `-o`. Prefer the just recipe.
- Installs `docs/site/node_modules` with `npm ci` only if `js-yaml` is missing.
  (`docs-build` / `docs-local` / `docs-offline` always run `npm ci` via
  `_docs-prepare`.)

Writes:

- `source/catalog-data.json`
- `source/applications/_category_.json` (hidden sidebar category)
- `source/applications/index.mdx` (`<AppCatalog />`)
- `source/applications/<app>.mdx` + `<app>.json` (one pair per app)
- `site/static/catalog-icons/<app>.{svg,png,jpg,gif,webp}`

Exits 1 if **no** catalog repos exist at `root`, or if two catalogs share the
same application directory name (flat URLs require globally unique names).

`generate-catalog` writes `source/catalog-data.json` and icons. It does **not**
copy the JSON to `site/static/catalog-data.json`. The listing UI fetches the
static copy. `_docs-prepare` (any `docs-build` / `docs-local` / `docs-offline`)
performs that copy. `docusaurus start` after only `generate-catalog` can show
a stale or missing catalog until prepare runs.

### `just generate-cli-docs`

Downloads released `nkp` CLIs and regenerates `source/cli/<minor>/`.

- Versions: `source/config.yaml` → `cliDocs.minors[]` (paths are MAJOR.MINOR;
  `latest` is the download tag). Current: `2.16←2.16.1`, `2.17←2.17.1`,
  `2.18←2.18.0` (default), plus unlisted `2.19←2.19.0-dev` (direct URL only).
- Published tarball (the `v` prefix is required on both the directory and the
  asset name; a URL without `v` returns 403):
  `https://downloads.d2iq.com/dkp/v<tag>/nkp_v<tag>_<linux|darwin>_amd64.tar.gz`
- OS is `darwin` or `linux` from `process.platform` (`NKP_CLI_OS` override).
  Arch defaults to `amd64` (`NKP_CLI_ARCH`).
- Cache: `docs/.cache/nkp-cli/<tag>/nkp` (gitignored). Reuse unless
  `--force-download`.
- For each minor: `nkp help --output markdown --tree --output-dir <tmp>`
  then keep flat Cobra `nkp_*.md` files, publish `nkp.md` as `index.md`,
  write `commands.json` (+ `site/static/cli/<minor>/commands.json`).
- Also syncs `site/src/data/cli-versions.json` (generated from `cliDocs`) for the React version select.
- Direct script: `node scripts/generate-cli-docs.mjs`. Also `--from-dir`,
  `--binary`, `--minor`, `--patch`. URL template: `NKP_CLI_URL` with
  `{version}` `{os}` `{arch}`.

Writes (wipes each `source/cli/<minor>/` first):

- `source/cli/<minor>/index.md` (`nkp` root) + flat `nkp_*.md` command pages
- `source/cli/<minor>/commands.json` and `site/static/cli/<minor>/commands.json`
- `source/cli/<minor>/_category_.json` (`className: hidden`)

Does **not** edit `source/cli/index.mdx`, `source/cli/_category_.json`, or `source/config.yaml`.

CI runs this before `docs-build`. Commit the generated trees when the task is
“refresh the CLI snapshot in git”. Do not hand-edit command pages.

### `just docs-build [base_url]`

GitHub Pages production build.

- Default `base_url='/nkp-partner-catalog/'`
- Depends on `_docs-prepare` then `_docs-export`
- Runs `BASE_URL=<base_url> npm run build` in `site/`
- Output: `site/build/`

### `just docs-local [host] [port] [base_url]`

Local preview of the **production** build (so search and Export work).

- Defaults: `host=0.0.0.0`, `port=3000`, `base_url=/`
- Prepare → export → `npm run build` → `docusaurus serve --dir build`
- Bind: `http://127.0.0.1:3000/` (and all interfaces)

This is a long-running server. PDF export needs Chrome (see §8).

### `just docs-offline`

Exports only. Copies PDF + HTML to `docs/dist/` **and** `site/static/offline/`.

### `just docs-deploy [branch] [repo]`

**Stage only. Does not commit or push.**

- Depends on `docs-build` (so production `baseUrl`)
- Clones or updates `docs/.docs-deploy` from
  `git@github.com:nutanix-cloud-native/nkp-partner-catalog.git` branch
  `gh-pages` (defaults)
- `rsync -a --delete --exclude='.git'` of `site/build/` into that clone
- `git add -A` and prints `git commit` / `git push` instructions

Defaults: `branch=gh-pages`,
`repo=git@github.com:nutanix-cloud-native/nkp-partner-catalog.git`

### Private recipes

- `_docs-prepare` — rsync schemas (`--delete`) from `source/schemas/v1/` →
  `site/static/schemas/v1/`; copy `catalog-data.json` into `site/static/`;
  `npm ci --prefer-offline --ignore-scripts` in `site/`
- `_docs-export` — `node scripts/build-exports.mjs --out-dir site/static/offline`.
  Sets `CHROME_PATH` if unset (macOS Chrome.app, then `chromium`,
  `chromium-browser`, `google-chrome`).

There is **no** public `docs-export` recipe. Export is `_docs-export` (private;
used by `docs-build`, `docs-local`, and `docs-offline`).

### Lower-level npm scripts (`docs/site/package.json`) — avoid unless debugging

| Script | What it does | Use? |
| --- | --- | --- |
| `start` | `docusaurus start` (dev server, no search index, no Export files unless already in static) | only for rapid UI iteration |
| `build` | `docusaurus build` | via `just docs-build` / `docs-local` |
| `serve` | **rebuilds** with `BASE_URL=/` then serves | redundant with `docs-local` |
| `start:with-search` | alias of `serve` | same |
| `deploy` | `docusaurus build && gh-pages -d build` — **pushes** | do not use |
| `clear` | `docusaurus clear` | ok |

`BASE_URL` and `SITE_URL` are read in `docusaurus.config.js`.
`normalizeBaseUrl()` forces a leading and trailing slash (`/` stays `/`).

**Live GitHub Pages is not limited to committed generated files.** CI runs
`generate-catalog` against freshly cloned sibling repos, then builds. A nightly
cron exists specifically to pick up new apps in the other two catalogs without
a commit here. Committed generated files exist so local preview and GitHub
browsing work without the siblings.

If you run `generate-catalog` locally, expect a large diff. Commit it when the
task is “refresh the catalog snapshot in git”. Do not commit it as drive-by
noise in an unrelated docs-copy change.

## 5. Catalog generation (deep)

Script: `docs/site/scripts/generate-catalog.js`

### Sibling layout

```
<org-root>/
  nkp-partner-catalog/
  nkp-ai-applications-catalog/
  nkp-nutanix-product-catalog/
```

`<org-root>` default inside the script is four levels up from
`docs/site/scripts/` (same as `docs/../../`).

Hard-coded catalog table:

| Repo dir | Display name | `slug` | Notes |
| --- | --- | --- | --- |
| `nkp-ai-applications-catalog` | AI Applications | `ai` | Stored as `catalogs[].slug` and each app’s `catalogSlug` |
| `nkp-partner-catalog` | Partner Catalog | `partner` | `catalogSlug` is **not** read by current React UI |
| `nkp-nutanix-product-catalog` | Nutanix Products | `nutanix` | Cards/detail show `catalog.name` / `catalogName`. There is **no** catalog facet. |

Missing sibling → warning + skip. Zero catalogs → exit 1.

Per-repo path override (not exposed by the just recipe):

```bash
node scripts/generate-catalog.js --root /org \
  nkp-ai-applications-catalog=/other/path
```

Unknown `id=path` keys warn and are ignored. Flags: `--root`, `-o`/`--output`.

### Scan rules (`scanApps`)

For each `applications/<name>/` directory (skip names starting with `.`):

- Version dirs must match `/^(\d+)\.(\d+)\.(\d+)/` (semver **patch required**).
  `2.19` as a folder name is skipped. `1.5.1-beta.0` **matches** as `1.5.1`.
- Latest version = last after `compareSemver`. Pre-release suffixes are
  **ignored** in the comparison, so `1.5.1-beta.0` can sort equal to `1.5.1`
  and become “latest” depending on directory order. Do not “fix” this in a
  drive-by; call it out if you touch version selection.
- Requires `applications/<name>/<latest>/metadata.yaml`. First YAML document
  in a multi-doc file is used (`yaml.loadAll`).
- Optional `applications/<name>/README.md` is attached as `readme` on the
  **detail** JSON only.

Fields copied from metadata:

`displayName`, `description`, `category[]`, `licensing[]`, `scope[]`, `icon`,
`overview`, `supportLink`, `dependencies[]`, `requiredDependencies[]`,
`allowMultipleInstances`, `nkpVersionSupport`, `type` (default `'custom'`),
`certifications[]`.

`allowMultipleInstances` is stored as `!!meta.allowMultipleInstances`, so a
missing field becomes **false**. The metadata schema’s default is **true**.
The detail page does not currently render this field.

### Icons

`metadata.yaml` `icon` is raw base64 (no data-URL prefix). Decoded to
`site/static/catalog-icons/<app>.<ext>`:

- PNG magic `89 50` → `.png`
- JPEG `FF D8` → `.jpg`
- GIF `47 49` → `.gif`
- WEBP `RIFF….WEBP` → `.webp`
- else `.svg`, with trailing whitespace stripped so pre-commit hooks pass

JSON then stores a **site-absolute URL** (`/catalog-icons/kyverno.svg`), never
base64. `AppIcon` still understands legacy inline base64 and `http(s)` URLs.

Empty/invalid icon → `""` and the UI shows a letter placeholder. Several
internal Nutanix apps currently have empty icons.

### Outputs

`catalog-data.json` shape:

```json
{
  "totalApps": 31,
  "nkpVersions": ["2.16", "2.17", "2.18", "2.19"],
  "catalogs": [
    {
      "id": "nkp-ai-applications-catalog",
      "name": "AI Applications",
      "slug": "ai",
      "repo": "https://github.com/…",
      "appCount": 15,
      "apps": [ { "name": "…", "icon": "/catalog-icons/….svg", "nkpRange": {}, "…": "listing fields" } ]
    }
  ]
}
```

Listing apps **omit** `overview` and `readme`. Detail `<app>.json` includes
them, plus `catalogName`, `catalogSlug`, `catalogRepo`.

Generated detail MDX:

```mdx
---
title: "Display Name"
description: "…"
sidebar_label: "Display Name"
unlisted: true
---

import AppDetailPage from '@site/src/components/AppDetailPage';
import data from './<app>.json';

<AppDetailPage data={data} />
```

Generated listing:

```mdx
---
title: Applications
hide_title: true
hide_table_of_contents: true
catalog_filters: true
---

import AppCatalog from '@site/src/components/AppCatalog';

<AppCatalog />
```

`catalog_filters` is written but **not read** by any component. Keep it if you
regenerate; do not build new behavior on it without wiring it up.

`applications/_category_.json`:

```json
{
  "label": "Applications",
  "position": 2,
  "className": "hidden",
  "collapsible": false,
  "link": { "type": "doc", "id": "applications/index" }
}
```

`.menu__list-item.hidden { display: none }` in `catalog.css` removes it from
the docs sidebar. Navbar **Applications** is the entry point. Breadcrumb
“Applications” still works via the category `link`.

### Application names must be unique across all three catalogs

Collision → `process.exit(1)` with a duplicate-name error. Check order in
`generate-catalog.js`:

1. Wipe `site/static/catalog-icons/` immediately.
2. Walk apps; on a duplicate **exit before** writing that app’s icon, before
   writing `catalog-data.json`, and **before** wiping `source/applications/`.
3. Icons for apps already walked are already on disk (folder was emptied).
4. Only after the walk succeeds: write `catalog-data.json`, then wipe and
   rewrite `source/applications/`.

The in-script comment about “writing anything” refers to the docs pages, not
icons. If you add an app, grep the other two catalogs for the same directory
name first.

### NKP version filter (`source/config.yaml` → `applications`)

Human-edited in `source/config.yaml`. Synced to `site/src/data/nkp-version-config.json`
by `generate-catalog` / `_docs-prepare`. Consumed by `nkpVersion.js` (Node + browser).

| Key | Value | Meaning |
| --- | --- | --- |
| `knownNkpVersions` | `2.16`–`2.20` | known product minors (fallback list) |
| `nkpVersionFloor` | `2.16` | empty `nkpVersionSupport` ⇒ “2.16+”, **not** “any version” |
| `maxGaNkpVersion` | `'2.19'` (env `MAX_GA_NKP_VERSION` overrides) | hide pre-GA minors from the dropdown |

`DEFAULT_NKP_VERSIONS` in `nkpVersion.js` is the GA-filtered fallback if
`catalog-data.json` has no `nkpVersions`.

`loadNkpVersions()` reads **this repo’s** `.release/stable.yaml` `releases[].constraints.nkpVersion`
(or `tagName`), unique-sorts, then `gaNkpVersions()`. On missing/unreadable
file it uses `DEFAULT_NKP_VERSIONS`.

`parseNkpRange()` understands `>=`, `>`, `<=`, `<` with optional `v` and
optional patch (`>=2.18.0` → min `2.18`). Bare `2.18` is a min bound.
Unparseable → floor from config.

When bumping a newly GA NKP version:

1. Add it to `.release/stable.yaml` if needed.
2. Add it to `applications.knownNkpVersions` in `source/config.yaml` if it is a new minor.
3. Bump `applications.maxGaNkpVersion` (and `docusaurus.config.js` `customFields.nkpVersion` /
   `nkpDocsBaseUrl` together).
4. Keep `scripts/build-exports.mjs` `NKP_VERSION` / `NKP_DOCS_BASE` in sync
  (they are **hardcoded `2.17` today** and can drift).

## 6. Applications UI

Routes (with local `baseUrl` `/`):

- `/docs/applications/` — listing (`AppCatalog`)
- `/docs/applications/<app>` — detail (`AppDetailPage`), `unlisted: true`

On GitHub Pages prefix both with `/nkp-partner-catalog`.

### Listing (`AppCatalog.js`)

- Fetches `useBaseUrl('/catalog-data.json')` (the **static** copy).
- Query params (shareable, `history.replace`): `category`, `nkp`, `cert`, `q`.
  Search input is debounced 300ms into `q`.
- Hides `type === 'internal'`. Those apps still get generated detail pages
  (reachable by URL). Listing is the only filter. Today that is
  `ncm-k8s-collector` and `ncm-k8s-collector-operator` (empty icons). Do not
  treat missing tiles or blank icons for `type: internal` as a listing bug.
- Facets: NKP version `<select>` (newest first), Support status, Category.
- Support status keys are **not** raw `certifications[]`. They come from
  `supportPanelKey()` in `categoryStyles.js`:
  - `type === 'preferred-partner'` → Preferred Partner
  - `type === 'nkp-catalog'` + cert `nutanix-supported` → Supported by Nutanix
  - `type === 'nkp-catalog'` otherwise → Qualified by Nutanix
  - anything else (including `nkp-core-platform`, `internal`, `custom`) → **no**
    support badge, even if `certifications` contains `qualified`
- `airgapped` in `certifications` is **not** a listing facet.
- Category labels: split on `-`, title-case (`inferencing-and-serving` →
  `Inferencing And Serving`).
- Cards link to `/docs/applications/${app.name}` via `useBaseUrl`.

### Detail (`AppDetailPage.js`)

Renders overview + README markdown with `marked` + `isomorphic-dompurify`.
Version tags link to
`${catalogRepo}/tree/main/applications/${name}/${version}` on GitHub.

### CLI reference

#### CLI UX principles (read before changing CLI UI)

Learned preferences — agents should follow these unless the user explicitly
overrides them:

| Do | Don't |
| --- | --- |
| Prefer short landing + hierarchical tree (chevron expand, no child-count badges); landing expands all by default; landing **Expand all** / **Collapse all** (a11y-named buttons); detail rail expands ancestors of active only | Ship a “product surface” that hides the shared left nav on `/cli`, decorate every branch with count pills, or expand-all in the detail rail |
| Keep one global left-nav item **CLI** (`sidebar_label: CLI`) with **no** command children; generated pages set `displayed_sidebar: tutorialSidebar` so the left nav still shows | Label the landing **Overview**, nest 100+ commands under CLI in `sidebars.js`, or omit `displayed_sidebar` (unlisted pages then lose the left nav) |
| Browse via expandable **tree** (short labels: `create` → `cluster` → `nutanix`) + search; version as **pills** for the GA support window | Flat 140-line filter list + lonely `<select>` as the main UX; put every historical minor in the pill strip |
| Clickable breadcrumbs on detail pages (`nkp › create › cluster › nutanix` → ancestors link) | Dead crumb text |
| **Parent (branch) pages:** description + **Available commands** child list only — no Options/flags | Dump Cobra flags on non-executable parents like `nkp create` |
| **Leaf pages:** one Doc title (no body H2); description without a “Synopsis” heading; **Options** (flat `dl.cli-opts`) → **Usage** → **Examples** (if any) → **Parent command** | Duplicate blue H2 under the title; “Synopsis” label; Options after Usage; inherited `<details>`; wide Options tables; grab-bag “See also” |
| Leave Cobra’s raw SEE ALSO out of generated output (rewritten as above) | Keep noisy multi-sibling SEE ALSO on hubs and leaves |
| Versions / floors in `source/config.yaml` (`cliDocs`, `applications`); **cliDocs** public pills ≈ **current + 2 prior GA** (~1 year at 3 releases/year); `unlisted` for pre-GA/dev; prune or hide EOL from pills (Older menu only if public listed minors exceed ~4) | Hardcode version lists only in `nkpVersion.js` / React; keep infinite history in the pill row |
| Nightly CI regenerates CLI (`deploy-docs` cron + `generate-cli-docs`; force-download on schedule) | Assume committed `source/cli/<minor>/` is always fresh on the live site |

**No curated “task cards”** on the landing unless the user asks. Humans would
have to own that IA in config; preferred model is the command tree itself,

## 8. Offline export (PDF / HTML)

Script: `docs/scripts/build-exports.mjs` (ESM).

Outputs (gitignored):

- `site/static/offline/nkp-catalog-docs.pdf` (preferred)
- `site/static/offline/nkp-catalog-docs.html` (open via `file://`)

Navbar Export uses `pathname:///offline/nkp-catalog-docs.pdf` (and `.html`)
via `offlineAssets.js`. The `pathname://` protocol stops Docusaurus from
treating the href as a missing docs route.

### What is included

Walks `docs/source/`, ordered by `_category_.json` `position` and
`sidebar_position`. **Skips:**

- `schemas/`
- `applications/` (SPA shells; not useful offline)
- `cli/<version>/` semver trees (full `nkp` dump; landing page is enough)
- files with `internal: true`, `draft: true`, `unlisted: true`, or
  `cli_generated: true`

MDX is crudely lowered to markdown: strip `import`s, replace
`siteConfig.customFields.*` with **hardcoded** `NKP_VERSION = '2.17'` and
portal URL `…-v2_17`, turn `<Link>` into markdown links, `<SchemaValidator/>`
into a blockquote, `<Tabs>` into `####` headings, admonitions into
`> **NOTE:**`. Residual capital-JSX tags log `warn: residual JSX in …`.

Then: markdown book → HTML (marked) → TOC from `h1`/`h2` → wrap in a
self-contained HTML document → print PDF with Chrome:

```
--headless=new --disable-gpu --no-first-run --disable-extensions
--no-pdf-header-footer --print-to-pdf=<path> --generate-pdf-document-outline
file://<html>
```

Retries without `--generate-pdf-document-outline` if the first pass fails.
Exits 1 if Chrome is missing, PDF missing, or PDF `< 1000` bytes.

Chrome resolution order: `CHROME_PATH`, `GOOGLE_CHROME_SHIM`, then well-known
macOS/Linux paths. `just _docs-export` also exports `CHROME_PATH` from PATH
helpers. Devbox installs `chromium` **only on Linux** (`x86_64-linux`,
`aarch64-linux`). On macOS, Google Chrome.app is expected.

Interactive features (validator, in-site search, catalog browser) are **not**
in the export. The HTML banner says so.
